# SteelBuild Pro — Client Conventions (read before writing any screen)

SteelBuild Pro is a Celoxis-style project portfolio app configured for a **structural steel erector (fabrication by others)**, Phoenix AZ. Users are PMs, superintendents, foremen, estimators, accounting. Speak their language: jobs, erection sequences, loads, fabricator, GC, EOR, RFIs, submittals, change orders (CO), backcharges, delay notices, crane, crew hours, tons erected, ST/OT, punch.

Stack: React 19 + Vite + Tailwind v4 + shadcn/ui (`@/components/ui/*`), wouter routing, tRPC v11 + React Query (`import { trpc } from "@/lib/trpc"`), superjson, sonner toasts, recharts, lucide-react icons. Server: Express + tRPC routers in `server/routers/*.ts` mounted in `server/routers.ts` (names: ref, admin, projects, tasks, baselines, deliveries, drawings, daily, resources, time, expenses, financials, wf, customFields, reports, collab, integration, dashboard). **Read the router file for exact input/output shapes before calling it.** Types flow end-to-end: `RouterOutputs["projects"]["get"]` via `import type { RouterOutputs } from "@/lib/ref"`.

## Design system — "Executive" (matches the SteelBuild Pro diamond-plate badge)

- Brand source: the user's real logo, the diamond-plate "STEELBUILD PRO" badge from steelbuild-pro.com (details in `/home/ubuntu/design/steelbuild-revamp/BRAND_SOURCE.md`). Files: `client/public/brand/steelbuild-pro-badge-480.webp` / `-960.webp` (cut out along the diamond, transparent corners, for dark backgrounds), `steelbuild-pro-icon-96.webp` (square app icon), `client/public/favicon-64.png`, `apple-touch-icon.png`. Never redraw or re-letter the logo.
- Palette: side menu **Foundry Black #0B0E11** (the logo's field) with **Signal Amber #F5BB00** (`--tp-brand`) only as the active-page marker, the org dot and menu badges. Work area is white panels on a light cool canvas (#F5F6F8), hairline rules #E3E7EC. Primary actions and links are **navy #1F3A5F** (`--tp-accent-ink`); data fills (progress, Gantt bars, charts) are steel blue #3B6A9A (`--tp-accent`). Amber is never used as text on white.
- Type: **Inter** everywhere in sentence case (page titles 24px/600, panel titles 15px/600, body 13.5–14px). **IBM Plex Mono** only for job numbers, sheet numbers and quantities (`.num`). `.label-caps` is a small muted sentence-case label (not all-caps); small all-caps is allowed only for side-menu section headers.
- Shape: 10px cards (`.tp-panel`), 6px buttons and inputs, soft shadows (`0 1px 2px rgba(16,24,40,.05)`), hairline borders. No hazard stripes, tape, stamps, heavy black rules, gradients, emoji or decorative illustrations.
- Status: `Pill` is a soft rounded pill (tinted fill, colored text, optional dot). Health always reads as dot + text, never color alone. On hold uses `tone="hazard"`, a dark slate pill (`--tp-hold` #344054); serious alerts (over budget, late) use red, optionally the solid red `hazard` variant. `.hazard` on a cell is a light red wash.
- Tables: `<table className="tp-table">` (sticky light header with muted 12px labels, hover rows, `tr.is-selected` = navy left bar + light blue tint, `td.right`). Panels: `.tp-panel` / `<Panel>`.
- Dialogs are 12px-radius white cards with a soft drop shadow; drawers have a hairline left edge and shadow.
- Interaction: click a row → open a right-side `RecordDrawer` (not a page jump, not a modal). Inline edit where reasonable. Optimistic or fast invalidation. Toast success briefly; toast errors with `errMsg(e)`.
- Copy voice: short, declarative, operational. "3 loads late." "Reforecast complete — finish moved 4 days." Empty states say what to do next. No "Welcome!" filler.
- Animations: none beyond shadcn defaults (120–180ms). Respect reduced motion (global CSS already does).
- Responsive: primary target 1280px+. Below 768px the side menu becomes a white bottom bar (My Work, Jobs, Timesheet, Approvals, Menu) and `main` gets 48px minimum tap targets (`.tp-touch`). Tab strips scroll horizontally; tab items must be `shrink-0`.

CSS tokens available as CSS vars: `--tp-graphite --tp-graphite-2 --tp-graphite-3 --tp-brand --tp-brand-ink --tp-bone --tp-paper --tp-rule --tp-rule-soft --tp-ink --tp-ink-2 --tp-muted --tp-accent --tp-accent-deep --tp-accent-ink --tp-accent-soft --tp-hold --tp-green --tp-green-soft --tp-amber --tp-amber-soft --tp-red --tp-red-strong --tp-red-soft --tp-blue --tp-blue-soft --tp-gray-soft`. Use as `bg-[var(--tp-accent)]` etc.

### Dark theme — legibility first

- Appearance is **Light / Dark / System**, controlled by `useTheme()` from `@/contexts/ThemeContext`; `theme` is the stored preference and `resolvedTheme` is the current light/dark palette. The user menu and top-bar sun/moon control persist `localStorage.theme`. System follows OS changes; the HTML head bootstrap applies `.dark` before first paint and synchronizes native `color-scheme` and browser `theme-color`.
- Work surfaces are tokens only: `bg-background` / `--tp-bone` for canvas, `bg-card` / `--tp-paper` for cards and inputs, `bg-popover` / `--tp-raised` for raised overlays, `--tp-surface` for table headers/hover, and `--tp-selection` / `--tp-checked` for row selection. **No `bg-white`, hard-coded neutral hex colors, or generic gray Tailwind palettes in UI chrome.** The descriptions above of white cards/light headers apply to Light; Dark uses the same geometry with steel-gray surfaces.
- Primary text is `--tp-ink` (dark `#eef2f6`, >=7:1); secondary is `--tp-ink-2`; muted is `--tp-muted` (dark `#aeb9c8`, >=4.5:1). Never use low-contrast gray-on-gray or dark text on dark fills. Links are `--tp-accent-ink`, **not `text-primary`**, because `--primary` is a button-fill role in Dark.
- White text is allowed only on fills that remain dark/colored in **both** themes: `--primary`, `--tp-solid`, `--tp-hold`, `--tp-red-fill`, or graphite. Never pair white labels with `--tp-ink`, `--tp-accent-ink`, or bright status text tokens. Status pills use the existing `Pill` dot + label and `--tp-*-soft` tinted fills; solid red uses `--tp-red-fill`, not `--tp-red-strong` (the latter is a bright text role in Dark).
- SVG can use `fill="var(--tp-ink)"` directly. Libraries/canvas needing actual colors must call `readCssToken("--tp-ink")` from `@/lib/theme` during redraw, **never at module scope**. React chart/canvas components use `useThemeTokens(STABLE_TOKEN_ARRAY)` from `@/hooks/useThemeTokens`; include the returned colors in redraw dependencies so System/theme changes refresh the artwork. Chart axes, legends, tooltip labels, and percentages always use text tokens, independently of series fills. Use `readableDataColor` to validate admin-chosen numeric text hues; keep a dot/underline color cue if text needs an ink fallback.
- **Drawings stay white paper:** sheet canvases, images, thumbnails, and PDF export use `--tp-drawing-paper` (fixed white) and `--tp-drawing-ink`, with stable saved annotation/highlight colors. Never invert/filter the actual drawing. Only surrounding toolbar, panels, input prompts, and dialogs adopt the theme.
- Additional tokens: `--tp-raised --tp-surface --tp-selection --tp-checked --tp-solid --tp-solid-ink --tp-red-fill --tp-orange --tp-orange-soft --tp-sidebar-muted --tp-sidebar-link --tp-sidebar-amber --tp-sidebar-red --tp-sidebar-orange --tp-sidebar-selected --tp-gantt-fill --tp-drawing-paper --tp-drawing-ink`. Full dark values and Python-measured WCAG contrast matrix: [`docs/DARK_THEME.md`](../docs/DARK_THEME.md). Regression checks live in `client/src/lib/theme.test.ts`.

## Privileges (server enforces; client just hides controls)

Project privileges (per job, via `useJob().can(p)`; exact keys from `shared/domain.ts`): `project.view project.edit project.delete project.financials project.manage_team task.edit task.progress baseline.manage delivery.edit dailyreport.create dailyreport.approve log.view log.create log.edit log.transition time.approve expense.approve document.upload comment.create`. Global: `project.create bid.manage report.create resource.view` via `useRefData().canGlobal(p)`. Admins (`isAdmin`) can do everything.

## Rules for parallel builders

1. Only create/modify the files assigned to you. Shared files (`App.tsx`, `index.css`, `components/brand/*`, `components/shell/*`, `lib/*`, `pages/job/JobLayout.tsx`, `pages/job/JobContext.tsx`) are owned by the lead — if you need a change there, put it in your final report instead.
2. Server changes: only in the router files assigned to you, only additive (new procedures or optional fields), keep existing procedure contracts intact, keep privilege checks. The dev server auto-reloads (`tsx watch`).
3. Type-check with `pnpm check`.
4. Do not use the browser. To inspect live response shapes you may run a tRPC caller script with `npx tsx` (see `scripts/smoke.ts` for the pattern; user openId `local:smoketest-admin` exists and is admin; demo data is loaded). The database is a dev copy that will be wiped before delivery — mutations are fine but clean up obviously junk records.
5. Write readable, well-structured code: split large screens into components under your `client/src/features/<area>/` folder. No `any` unless unavoidable. No console.log left behind.
6. Final report: list files created/changed, any server procedures added, any requested changes to shared files, and known gaps.
